[FIXED] 1. [CRITICAL-01] HTTP PUT vs PATCH Mismatch
- Frontend Changes:
  * `frontend/src/services/accountService.ts`: Switched `apiClient.put` to `apiClient.patch('/accounts/' + id, updates)`.
  * `frontend/src/services/transactionService.ts`: Switched `apiClient.put` to `apiClient.patch('/transactions/' + id, updates)`.
  * `frontend/src/services/budgetService.ts`: Switched `apiClient.put` to `apiClient.patch('/budgets/' + id, updates)`.
- Backend Changes:
  * `backend/src/routes/account.routes.ts`: Registered `router.put('/:id', requireAuth, updateAccount)` alongside `.patch()`.
  * `backend/src/routes/transaction.routes.ts`: Registered `router.put('/:id', requireAuth, updateTransaction)` alongside `.patch()`.
  * `backend/src/routes/budget.routes.ts`: Registered `router.put('/:id', requireAuth, updateBudget)` alongside `.patch()`.
- Impact: Seamless bidirectional compatibility; updates never fail with HTTP 404/405.

[FIXED] 2. [CRITICAL-02] Offline/Local Mode 503 Crash on Dashboard
- Backend Changes:
  * `backend/src/services/financial.service.ts`: Removed empty/throw stub and implemented in-memory `localStore` calculation for `calculateFinancialOverview` and `calculateCategoryBreakdown` when `!supabaseAdminClient`.
  * `backend/src/services/dashboard.service.ts`: Removed fatal `throw new AppError('Database service unavailable', 503)`. When Supabase cloud is unconfigured, dashboard metrics, profiles, transactions, and trend buckets compute seamlessly from `localStore`.
- Impact: Dev/offline mode starts cleanly with zero 503 crashes on `/api/v1/dashboard/metrics`.

[FIXED] 3. [HIGH-01] Empty Environment Variable URL String Boot Crash
- Backend Changes:
  * `backend/src/config/env.ts`: Wrapped `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `GEMINI_API_KEY`, `OPENROUTER_API_KEY`, and `SENTRY_DSN` with `z.preprocess((val) => (val === '' ? undefined : val), ...)` to allow empty `.env` strings safely without crashing boot.
- Impact: Server boots without crashing when `.env` contains placeholder keys.

[FIXED] 4. [HIGH-02] SQL Injection Sanitizer False Positives
- Backend Changes:
  * `backend/src/middleware/sanitizer.ts`: Replaced the greedy `.*` SQL regex with precise syntax-targeting patterns: stacked queries with `;`, SQL comments (`--`, `/* */`), boolean tautologies (`OR 1=1`), and `UNION SELECT`.
- Impact: Legitimate searches like "Drop into the store" or "Update table lamps" are never falsely blocked with HTTP 400.

[FIXED] 5. [HIGH-03] Strict UUID Validator Breaking Demo Account IDs
- Backend Changes:
  * `backend/src/validators/transaction.validator.ts`: Relaxed `accountId` schema to `z.string().trim().min(1).regex(/^([0-9a-fA-F-]{36}|acc-[a-zA-Z0-9-]+)$/)`.
- Impact: Accepts both standard 36-char UUIDs and seeded accounts (`acc-hdfc-01`, `acc-icici-02`, etc.).
