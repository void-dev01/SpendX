3. Root Cause Analysis: "Features Kam Kyun Nahi Kar Rahe The?" (Why Features Appeared Broken):
   - Whenever the backend server on port 5000 was offline or Supabase was not connected:
     a) accountService.getAccounts() caught API network errors and returned an empty array `[]` instead of returning the user's stored accounts.
     b) transactionService.getTransactions() caught API network errors and line 370 returned `return [];` instead of returning stored transactions from localStorage.
     c) budgetService.getBudgets(), savingsService.getGoals(), and recurringService.getRecurringPayments() all returned `return [];` on network error.
     d) When creating a new account or transaction, the create mutation succeeded locally, but queryClient.invalidateQueries() immediately triggered a refetch that caught an API network error and returned `[]`, causing newly created records to instantly vanish from the screen.
     e) In TransactionFormDialog.tsx, accounts were hardcoded to DEFAULT_USER_ACCOUNTS (4 static demo accounts) rather than reading the user's active accounts. Users could not select their newly created accounts when adding transactions.
     f) In dashboardService.ts, line 733 and line 907 prematurely returned hardcoded empty zero-state objects, preventing the real ledger computation engine (lines 948-1064) from aggregating metrics from local storage.

4. Implementation of Full Offline & Online Resilience:
   - All 5 core frontend domain services (accountService, transactionService, budgetService, savingsService, recurringService) now:
     * First attempt the backend API.
     * On API success: automatically cache the fresh server data into localStorage.
     * On network/offline/local failure: immediately fall back to localStorage without throwing errors or clearing user records.
     * On create/update/delete: update both the remote API and the local cache simultaneously so data remains 100% persistent and visible under all network conditions.
   - TransactionFormDialog dynamically loads user accounts via accountService.getStoredAccounts() and props, falling back to a clean "Cash / Primary Wallet" if no accounts exist yet.
   - dashboardService.ts now deterministically aggregates all real transactions, accounts, budgets, savings goals, and recurring schedules from the local verified ledger whenever the backend is offline.
   - Removed fake sample demo benchmark overrides (`DEMO_DASHBOARD_DATA` and `isDemo: true` badges) so user data starts clean and authentic.
