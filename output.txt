2. HYBRID BACKEND ARCHITECTURE SPECIFICATION
================================================================================
SpendX implements a two-tier Hybrid Backend designed to balance ultra-low-latency
edge capture with heavy compute and persistent background operations:

A. Part 1: Express.js Core Microservice (/backend)
   - Runtime: Node.js 26 LTS, Express 4.21, TypeScript 5.7
   - Responsibilities:
     1. Transactions API: Full REST CRUD (`GET /`, `POST /`, `POST /batch`, `GET /:id`,
        `PATCH /:id`, `DELETE /:id`) with 24-hour duplicate detection window.
     2. Budgets API (`/api/v1/budgets`): Category spending caps, real-time utilization
        meters, and threshold checks (`>80%` warning alerts, `100%` critical breaches).
     3. Savings Goals API (`/api/v1/savings`): Goal initialization, contribution ledger,
        and milestone progress evaluators (`50%` halfway mark, `100%` completion).
     4. Financial Analytics API (`/api/v1/analytics`): Net worth telemetry, income vs.
        expense burn rates, runway projection, and deterministic 4-Pillar Financial Health Score (0-100).
     5. Import API (`/api/v1/import`): Validation, batch committing, and `capture_events` logging.
     6. AI Intelligence Service: 2-tier hybrid intelligence combining deterministic
        regex rules (fast path) with Google Gemini (`@google/genai`) Structured JSON fallback
        strictly validated via Zod schemas (`smartCategorizationSchema`, `merchantIdentificationSchema`,
        `monthlySummarySchema`, `budgetRecommendationSchema`).
     7. Observability: Sentry Node integration (`@sentry/node`) with graceful no-op.

B. Part 2: Supabase Edge Functions (/supabase/functions)
   - Runtime: Deno TypeScript runtime on Supabase Edge Network (sub-100ms cold start)
   - Deployed Edge Functions:
     1. `quick-capture` (`supabase/functions/quick-capture/index.ts`):
        - Rapid SMS, UPI notification, and raw note ingestion.
        - Instant regex extraction (amount, merchant, date, reference number).
        - 24-hour deduplication window check against existing transactions.
        - Persists audit log into `capture_events` and inserts into `transactions`.
     2. `smart-categorize` (`supabase/functions/smart-categorize/index.ts`):
        - Stateless, high-speed merchant identification and category categorization.
        - Tier 1 regex dictionary for Indian merchants (Swiggy, Zomato, Uber, Amazon, etc.).
        - Tier 2 Gemini REST fallback with structured JSON validation.
     3. `webhook-alerts` (`supabase/functions/webhook-alerts/index.ts`):
        - Event-driven alert dispatcher for database triggers and webhook pings.
        - Validates against user preferences in `notification_preferences`.
        - Emits real-time notifications for budget breaches, bill reminders, and goal milestones.
     4. Shared Edge Utilities (`supabase/functions/_shared/`):
        - `cors.ts`: Unified CORS headers and OPTIONS preflight responder.
        - `auth.ts`: Supabase Auth JWT verification with offline mock fallback.

4. DATABASE MIGRATIONS & SCHEMA ARCHITECTURE
================================================================================
Database migrations are housed in `backend/src/db/migrations/` and follow strict execution order:
1. `001_initial_schema.sql`  : 14 core entities + 11 primary B-Tree indexes.
2. `002_row_level_security.sql`: Multi-tenant RLS policies on all tables (`auth.uid() = user_id`).
3. `003_audit_triggers.sql`   : `set_updated_at()` trigger and `handle_new_user()` auto-provisioning.
4. `004_hybrid_alignment.sql` :
   - Table `notification_preferences` for edge alert rules & multi-channel preferences.
   - Composite B-Tree indexes:
     - `transactions(user_id, date DESC)`
     - `transactions(user_id, date DESC, type)`
     - `transactions(user_id, category)`
     - `budgets(user_id, category)`
     - `savings_goals(user_id, target_date)`
     - `recurring_payments(user_id, next_due_date, status)`
     - `notifications(user_id, is_read, created_at DESC)`
     - `capture_events(user_id, created_at DESC)`
   - View `recurring_transactions` standard alias for cross-system query compatibility.
   - Strict RLS policies on `notification_preferences`.
